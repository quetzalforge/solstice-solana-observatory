# Solstice — Solana Ecosystem Observatory

Solstice turns live Solana network and market data into one automatically updating field report. It combines direct JSON-RPC measurements with public DefiLlama feeds, then publishes the same snapshot as an interactive HTML dashboard, machine-readable JSON, and human-readable Markdown.

> Live demo: deployment URL is added here during release.

## What makes it useful

- **Network pulse:** TPS, non-vote TPS, slot time, slot height, epoch progress, transaction count, core version, and circulating supply.
- **Validator resilience:** active and delinquent vote accounts, delinquency share, and active stake.
- **Economic layer:** SOL price and seven-day change, Solana TVL, stablecoin supply, and 24-hour DEX volume.
- **Detection engine:** z-score throughput detection plus explicit slot-time and validator-delinquency rules.
- **Graceful degradation:** one broken source never hides healthy data. Every source exposes state, latency, and provenance.
- **No API keys:** the default configuration uses only public Solana RPC and public DefiLlama endpoints.
- **Three outputs:** interactive HTML, downloadable JSON, and Markdown.

## Run it in four steps

1. Install dependencies with `pnpm install`.
2. Start the dashboard with `pnpm dev`.
3. Open `http://localhost:3000`.
4. Optional: run `python scripts/collect.py` to generate static JSON and Markdown reports using only Python's standard library.

No `.env` file is required. To use another public or private RPC, set `SOLANA_RPC_URL` before starting the app or collector.

## Architecture

```text
Solana JSON-RPC ─┐
                 ├─ concurrent collector ─ normalization ─ detection rules
DefiLlama APIs ──┘                                      │
                                                       ├─ interactive HTML
                                                       ├─ /api/report?format=json
                                                       └─ /api/report?format=md
```

The deployed dashboard refreshes its snapshot every five minutes. The included GitHub Action also runs the zero-dependency Python collector hourly and commits reproducible static samples to `public/data/latest.json` and `public/reports/latest.md`.

## Data sources

| Source | Data | Integration |
| --- | --- | --- |
| Solana JSON-RPC | health, version, slot, epoch, performance samples, vote accounts, supply, transactions | One batched POST request |
| DefiLlama Chains | current Solana TVL | Public REST endpoint |
| DefiLlama Coins | current and seven-day SOL price | Public REST endpoint |
| DefiLlama Stablecoins | circulating stablecoin supply on Solana | Public REST endpoint |
| DefiLlama DEX Overview | 24-hour DEX volume and 30-day trend | Public REST endpoint |
| DefiLlama Historical TVL | 30-day TVL trend | Public REST endpoint |

All data cards preserve nulls instead of inventing values. A degraded endpoint is shown in the source table and recorded as a signal.

## Detection method

Solstice intentionally uses transparent rules that a reviewer can audit:

- **TPS anomaly:** the latest performance sample is compared with the remaining recent samples. A two-standard-deviation move is a warning; three is critical.
- **Slot-time anomaly:** over 600 ms is a warning and over 800 ms is critical.
- **Validator delinquency:** above 2% is a warning and above 5% is critical.
- **Source health:** failed and timed-out sources are reported without blocking other results.

This is a monitoring heuristic, not a prediction or trading signal.

## Output contracts

- `GET /api/snapshot` — normalized live snapshot used by the dashboard.
- `GET /api/report?format=json` — downloadable live JSON.
- `GET /api/report?format=md` — downloadable live Markdown.
- `public/data/latest.json` — checked-in sample generated by the Python collector.
- `public/reports/latest.md` — checked-in human-readable sample.

## Automation and maintenance

The collectors use bounded request timeouts and concurrent source reads. Adding a new source requires one fetch, one normalization block, and one source-health entry. The front end consumes a stable normalized contract and does not know vendor-specific response shapes.

The dashboard is deployable as a Cloudflare-compatible worker through OpenAI Sites. CI verifies the production build and server-rendered product shell.
